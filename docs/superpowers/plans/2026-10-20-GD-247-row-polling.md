# GD-247 행별 조회·폴링·갱신 실패 UX 구현 계획

> 2026-10-20 사용자가 권장안 1을 승인했다. `executing-plans`로 구현했으며 아래 실행 기록과 보고서에 검증 결과를 연결한다.

**목표:** 표시 범위 밖의 주기 요청을 줄이고 확정된 종결 상태에서 조회를 중지하며 갱신 실패에도 마지막 성공값을 유지한다.

**구조:** 기존 TanStack Query 캐시와 행별 키를 유지한다. 화면이 조회 대상과 폴링 활성 여부를 전달하고 결과 훅이 계약에 근거한 종료 조건을 적용한다.

**기술:** 기존 React·TanStack Query·Axios·Vitest·Testing Library·MSW만 사용한다.

**근거:** 로드맵 R09, ADR-0007, 공용 명세 `05-api/entry.md`, `drawing.md`, `common.md`, 사용자 GD-247 요청.

## 제약

- SSE/WebSocket·새 dependency·전역 상태·환경 변수·설정 변경을 추가하지 않는다.
- API 계약을 임의 변경하지 않는다. 승인 전 제품 코드·테스트를 작성하지 않는다.
- 기존 미추적 로드맵·세션 프롬프트·배포 보고서를 보존한다.
- 응모 내역 E06·이벤트 E01 전체 수집 제거는 미완료 R08 후속이며 이번 변경으로 완료 처리하지 않는다.
- 보이는 행은 화면에서 렌더링하는 페이지/더보기 범위다. 스크롤 viewport 감지는 추가하지 않는다.

## 현재 요청 범위·키·정책 측정

아래 수치는 코드 경로로 산출한 기준값이며 네트워크 실측으로 가장하지 않는다. 승인 후 같은 fixture의 fake timer 요청 카운터로 전후 값을 확정한다. 성공·콜드 캐시·다른 소비자 없음·탭 활성 조건이다.

| 대상             | 키·범위                                                    | 최초 / 30초 / 60초 누계           |
| ---------------- | ---------------------------------------------------------- | --------------------------------- |
| 마감 E03 preview | entries/statistics/eventId, 첫 3행                         | 3 / 3 / 3                         |
| 마감 E03 full    | 같은 키, 첫 10행, 더보기마다 최대 10행 추가                | 10 / 10 / 10                      |
| 내 응모 E09      | draw-results/eventId/me, 전체 접수 이벤트 ID 중복 제거 A개 | 미공개 A개이면 A / 2A / 3A        |
| E08·단건 E09     | draw-results/eventId 및 위 me 키 공유                      | 미공개 취소도 각각 1 / 2 / 3      |
| E01              | events/list, 전체 페이지 P개                               | P / 2P / 3P                       |
| E06              | entries/me, 전체 페이지 Q개                                | Q / Q / Q, 무효화·재마운트는 별도 |

- E03은 기본 isOpen=false로 마감 행 주기 조회가 이미 없다. 현재 slice 밖의 행도 마운트되지 않아 요청하지 않는다. 이 사실을 회귀 테스트로 고정한다.
- realtime staleTime=0, refetchInterval=30초. 전역 retry=1, 창 포커스 재조회=false. 설치된 기본 retryDelay는 최초 1초다. 400/403/404/429도 현재 1회 재시도한다.
- 숨긴 탭의 interval은 기본값으로 정지하지만 초기 요청·진행 중 요청·재시도 전체가 일괄 취소되는 것은 아니다. 재시도와 interval을 따로 측정한다.
- Axios ApiError.retryAfterSeconds에 헤더가 저장되지만 쿼리 재시도는 이를 사용하지 않는다.
- Query 캐시는 재조회 실패 때 data를 유지한다. 다중 E03 combine은 isError이면 null을 반환해 기존 값을 가린다. LiveEntryStatus는 실패 안내·수동 재시도·마지막 성공 시각을 제공하지 않는다.
- 내 응모 화면은 결과 전체를 받아 상태별 건수·필터·최근 당첨일을 계산한다. 마이페이지는 4행만 표시하지만 전체 결과를 요청해 프로필 요약을 계산한다.

## 승인할 조회 범위 선택

엄격한 ‘최초 요청도 보이는 행만’과 ‘전체 결과 필터·정확한 전체 집계 유지’는 현재 E06/E09 계약으로 동시에 달성할 수 없다. E09 조회 전에는 숨긴 응모가 WON/LOST인지 알 수 없다.

1. **권장, 기존 기능 유지:** 집계에 필요한 최초 E09는 현재 범위 전체를 읽되 자동 주기 조회는 렌더링된 행의 접수 이벤트만 활성화한다. 숨긴 행은 캐시를 사용하며 집계는 마지막 조회 기준임을 표시한다. 전체 결과 재조회는 명시적 조작으로만 수행한다. 최초 요청량 절감은 계약 후속으로 남긴다.
2. **엄격한 표시 범위 제한:** 최초부터 표시 행만 E09를 읽는다. 전체 당첨/미당첨 필터·건수·최근 당첨일은 정확성을 보장할 계약이 생길 때까지 미지원 또는 조회 범위 한정으로 바뀐다. 이 제품 동작 변경은 별도 명시 승인이 필요하다.

사용자가 1을 승인했다. 아래 구현·검증은 최초 전체 집계 조회를 유지하고 표시 행만 주기 조회하는 범위로 수행한다.

## 작업 2: 종료·재시도 정책

- [x] E08은 isPublished 또는 확정된 CANCELED/NO_ENTRANTS에서 interval=false로 한다. E09 모호한 입력은 기존 조회를 유지한다.

- [x] 네트워크/5xx는 1회 재시도 후 활성·비종결 항목만 다음 30초 주기에 재조회한다.
- [x] 429는 유효한 Retry-After까지 자동 재시도·interval·수동 재시도가 우회하지 못하도록 한다. 헤더가 없으면 30초를 FE 보수적 대기로 사용하고 서버 계약값으로 설명하지 않는다. 서버 대기 90초 fixture로 30/60초 요청 0회를 검증한다.

- [x] 기존 ApiError·오류 문구를 재사용한다. 변경한 queryFn에 signal을 전달하고 제거된 행의 늦은 응답이 다른 행에 표시되지 않도록 키별 캐시를 유지한다.
