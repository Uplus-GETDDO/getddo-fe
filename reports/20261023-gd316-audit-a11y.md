## 검증 방법·증거

- 실행: `python scripts/verifyGd316AuditA11y.py`. Playwright Python과 Chromium이 설치된 환경에서 수행한다.
- dev 서버는 `VITE_ENABLE_MSW=true`, `VITE_API_BASE_URL=/api`, `VITE_VIRTUAL_USERS_JSON`에 목업 관리자 `vu-admin`을 포함한 JSON을 프로세스 환경으로 주입하고 `npm run dev -- --port 5199 --strictPort`로 실행한다. 기존 `.env`는 변경하지 않는다.
- 로그인·상세 열기·운영 이력 선택·페이지 전환·닫기는 Tab·Shift+Tab·Enter·Escape로 수행한다. 스크롤 영역은 ArrowRight로 실제 수평 이동을 확인한다.
- 기본 1280×900, 320×900, 네이티브 200% 확대에서 각각 정방향 18회·역방향 18회 포커스 순회를 측정한다. 감사 페이지는 10행→2행→10행으로 전환한다.
- 200%는 임시 Chromium 확장의 `chrome.tabs.setZoom(tabId, 2)`와 `getZoom=2`로 확인한다. CSS `zoom`이나 DPR 변경으로 대체하지 않았다. 창 1280×900에서 실제 CSS 뷰포트는 632×402, DPR은 2다.
- 임시 확장·프로필은 검증 프로세스에만 존재한다. 제품에 설치하거나 의존성을 추가하지 않는다. 네이티브 확대 화면은 CDP compositor 캡처로 저장한다.
- 감사 목록은 브라우저 안에서 기존 MSW worker에 합성 12행을 주입한다. null·긴 사유·긴 요청 ID·다중 페이지를 검사하며 실제 운영 감사 기록으로 주장하지 않는다.

## 남은 리스크

- 이번 판정은 실행 감사 표의 키보드·320px·200% 범위다. 스크린 리더 실사용, 전체 관리자 화면의 접근성 인증, 다른 브라우저 엔진 검증은 포함하지 않는다.
- 320px에서 모달 본문의 `scrollWidth`가 `clientWidth`보다 큰 보조 측정값이 남지만 감사 섹션은 모달 경계 안에 있고 표의 수평 이동·포커스 조작이 가능하다. 페이지·모달 외곽 넘침, 감사 셀 잘림·행 겹침과 구분한다.
- 실패 이력 표 등 감사 표 밖의 좁은 열 줄바꿈은 이번 범위에서 재설계하지 않았다.
- L2/L5의 미완료 인수·실패 실행 재개·실제 자정/월 경계·관리자 게임 운영 범위는 각 담당자의 후속이다. 기존 인수 보고서만으로 최신 환경의 완료를 단정하지 않는다.
- PR 머지는 사용자 승인 전 수행하지 않는다.
