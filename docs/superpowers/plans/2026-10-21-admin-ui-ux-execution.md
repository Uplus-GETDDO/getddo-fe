# 관리자 추첨·이미지·UI·UX 개선 실행 프롬프트 및 계획

> 실행자는 `executing-plans` 스킬로 아래 작업을 순서대로 수행하고 체크박스로 진행 상태를 기록한다. 이 파일 작성은 제품 코드 구현 승인을 의미하지 않는다. 아래 시작 프롬프트를 사용자가 실행 요청으로 전달하면 승인 경계를 확인하고 진행한다.

**목표:** 관리자에게 추첨 진행·결과 검토·공개 상태를 명확히 보여주고, 상세 모달·페이지 설명·이미지·레이아웃을 일관되게 개선한다.

**구조:** 기존 FSD와 TanStack Query를 유지한다. 서버 업무 상태와 화면 조회 상태를 구분하며, 공개 사실은 서버의 공개 응답·이력에 근거한다. 기존 Dialog·디자인 토큰을 재사용하고 기능별 변경과 검증을 작은 단위로 진행한다.

**기술:** TypeScript, React, Vite, TanStack Query, TailwindCSS, shadcn/ui, Vitest, React Testing Library, MSW.

**명세:** `getddo-spec/02-domain/drawing.md`, `getddo-spec/05-api/drawing.md`, ADR-022, ADR-026 및 이 문서의 인수 기준.

**작성 기준:** 2026-10-21, FE `dev` 커밋 `25268db`. 실행 시 현재 브랜치·커밋·작업 트리와 최신 명세를 다시 확인한다.

## 2. 실행 규칙과 승인 경계

- 항상 한국어로 응답하고 코드·문서는 프로젝트 관례를 따른다.
- `git branch`·`git status` 확인 → 프로젝트 AGENTS.md·README·관련 명세 읽기 → 영향 평가 → 구현 → diff·검증 순서를 지킨다.
- 현재 승인된 Jira 키가 없다면 새 키나 브랜치 이름을 만들지 않는다. 브랜치 정책상 필요하면 실제 키를 확인하고 다른 작업과 섞지 않는다.
- 기존 유틸·컴포넌트를 검색해 재사용한다. 같은 레이어 슬라이스 간 참조·딥 임포트를 추가하지 않는다.
- 서버 데이터는 TanStack Query가 관리한다. Zustand 등에 복사한 별도 서버 상태를 만들지 않는다.
- 새 의존성, DB schema, API contract, auth 로직, 상태관리·라우팅·폴더 아키텍처, 환경 변수, eslint·tsconfig·빌드 설정 변경은 구체안 승인 후 진행한다.
- lint·포맷·IDE 진단만을 이유로 범위 밖 코드를 자동 수정하지 않는다. 필요한 범위 밖 수정은 설명한다.
- 비밀 정보·개인정보·인증 헤더 원문을 문서·스크린샷·네트워크 증거에 남기지 않는다. 기존 `.env`를 덮어쓰지 않는다.
- 실행 시 `obsidian-knowledge-base`로 관련 템플릿·오류 기록·자산 카드를 조회한다. 과거 패턴은 Stale-Knowledge Gate를 통과한 뒤 사용한다. 접근 불가 여부는 기록하고 현행 코드·명세로 진행한다.
- 버그는 `systematic-debugging`, 구현은 `executing-plans`·관련 UI/접근성 스킬, 완료 판정은 `verification-before-completion`·`common-reporting-guide`를 적용한다.

## 6. 작업 B — 추첨·검증·공개 경계 수정

- [x] 시간 경과·추첨 완료·정합성 검증만으로 공개되지 않는 회귀 테스트를 먼저 추가하고 실패를 확인한다.
- [x] 목업 자동 공개를 제거한다. 이미 공개된 시연 데이터가 필요하면 명시적인 시드로 구분하고 신규 흐름과 섞지 않는다.
- [x] 관리자 이벤트·실행·공개 이력·사용자 결과가 같은 공개 사실을 반영하도록 기존 상태 소유 위치를 찾아 정합화한다. 새 범용 저장소·순환 의존을 만들지 않는다.
- [x] `최초 발표`를 `당첨자 공개`, 공개 이후 변경 작업을 `공개 명단 갱신`으로 통일한다. 동작·응답은 기존 계약을 유지한다.
- [x] 미공개이고 현재 계약의 준비 조건을 만족한 최신 검토 실행에서만 공개한다. 진행 중·실패·취소 이벤트·확정 결과 누락·공개 여부 조회 실패에는 공개를 막고 이유를 표시한다.
- [x] 공개 직전 확인 모달에 이벤트·공개 인원·미충원·취소/재추첨 반영 여부와 사용자 노출 영향을 표시한다. 명단 동일성은 기존 서버 검증에 맡기고 임의 DTO를 추가하지 않는다.
- [x] 요청 중 중복 클릭을 막는다. 성공 응답을 스키마로 검증하고 실제 공개 식별자·버전·시각과 공개 여부에 따라 성공을 표시한다.
- [x] 오류·충돌이면 최신 데이터를 재조회하고 재검토를 안내한다. 화면 상태만 강제로 `발표 완료`로 바꾸지 않는다.
- [x] 공개·갱신 성공 시 관련 관리자 이벤트·실행·공개 이력·사용자 결과 쿼리를 기존 키로 갱신한다. 기존 알림 연동·중복 방지를 유지한다.
