# GD-262 최종 측정 보고서

## 판정과 범위

결과 커밋 `14764f7`, [dev 대상 PR #131](https://github.com/Uplus-GETDDO/getddo-fe/pull/131)을 작성했다. 기존 Vercel 연동의 PR preview 자동 생성은 관측했으나 직접 머지·프로덕션 배포 명령은 실행하지 않았다. PR CI와 필수 리뷰는 최종 반영의 별도 조건이다.

**11개 사용자 화면 lazy 분리를 초기 JS bytes 최적화로 채택한다. 전체 화면 시간 개선으로 채택하는 것은 아니다.** dev `aa34107`과 dev 머지 후보 `47d2b54`의 초기 gzip은 404,679→349,840B(-13.55%)다. 홈 시간 차이는 배치 변동을 넘지 않았으며 게임·겟또타임 상세 전환은 느려졌다. 이 비용을 숨기거나 새 시간 합격선을 임의로 만들지 않는다.

- 기존 `perf/GD-262` 전용 worktree에서 dev를 충돌 없이 머지했다. 원본은 별도 detached worktree다. 완료된 lazy·회귀 테스트를 재구현하지 않았다.
- 제품 차이는 `userRoutes.tsx`·인접 회귀 테스트뿐이다. 이번 재개에서는 도구 오류 수정·고정 응답 보완·증거 작성만 추가했다.
- Windows, Node 24.14.1, npm 11.11.0, Chrome 155.0.8059.85 headless, 기존 Playwright를 재사용했다.
- 통제 372시도·348유효·24 NA·실패 0·API 오류 0·관측된 동일 입력 동시 중복 0이다. 브라우저 7개 검사 그룹도 통과했다. 최종 전체 품질 검증은 진행 중이다.
- 원문 fixture는 Git 밖에만 둔다. 실서버 쓰기·머지·배포는 하지 않았다. 수집은 누락 E03 4건의 명시적 GET만 수행했고, 재생 시 미수집 요청은 502로 차단했다.

고정 응답 출처·해시·보완 절차와 끝점의 한계는 [측정 조건](controlled3-methodology.md)을 따른다. 주 측정·101건·체류는 별도 고정 파일이며 **각 실험 안에서 전후 해시가 일치한다**. 서로 다른 fixture를 합쳐 개선율을 만들지 않았다. [빌드 해시](controlled3-build-identities.json)가 제공된 소스를 식별한다. 원시 JSON의 environment.commit은 도구 실행 폴더의 커밋이지 원본 빌드의 소스가 아니다.

측정 중 원격 dev가 `9ffbf4f`로 진행했다(GD-263 읽기 증거·GD-290 공통 입력 스타일). 기준선은 작업 시작 때 fetch한 `aa34107`로 고정하며 다른 세션 변경을 덮어쓰지 않는다. 후속 dev 변경을 포함한 성능 수치로 해석하지 않는다. PR의 최신 dev 통합 CI·리뷰와 이 고정 소스의 성능 실험을 구분한다.

## 갱신안·후속·복귀

- `backend-integration-status.md`는 수정하지 않는다. 갱신안: “GD-262는 dev aa34107 기준 통제 372시도(348유효·24 NA)와 브라우저 7개 그룹을 검증했다. 초기 JS gzip -13.55%로 lazy를 채택하되 홈 시간 개선은 미확정, 게임·겟또타임 상세 전환 비용과 전체 JS 증가가 있다. format/lint/전체 테스트(849)/build/diff 검사를 통과했다. 실제 공개→화면·응모 쓰기·서버 내부/부하·알림 목표는 미검증이다.”
- 기존 BE 후속인 E06 전체 합계/결과 필터 요약, E09 다건, M01 questionCount, 게임 사용자 통계, 공개→화면 목표와 폴링의 차이는 유지한다. 새 계약·합계·캐시 정책을 임의 확정하지 않는다.
- RUM·성능 CI 예산·사람의 과제 수행 표본은 없다. 새 의존성/빌드 설정 없이 재현 가능한 측정 스크립트와 기존 로딩 회귀 테스트만 남긴다. 실제 배포의 성능 합격 판정은 별도 인수다.
