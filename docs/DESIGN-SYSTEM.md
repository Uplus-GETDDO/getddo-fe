## 0. 사용 원칙 (에이전트가 지킬 것)

1. **하드코딩 금지**: 컴포넌트 코드에 `#E6007E` 같은 hex 값을 직접 쓰지 말고, 반드시 아래 토큰명(`brand/primary` 등)에 매핑된 CSS 변수·디자인 토큰을 통해 참조한다.
2. **의미(semantic) 우선**: 같은 색이어도 "무엇에 쓰는가"에 따라 다른 토큰명을 쓴다.
3. **관리자 전용 vs 사용자 전용 구분**: `status/*`, `chart/*`는 관리자(운영자) 화면 전용, `play/*`는 사용자(응모자) 사이트 전용.
4. **값의 원천**: 이 문서의 모든 값은 Figma 도형에 실제로 바인딩된 Variable/Effect 값을 기준으로 작성했다 (캔버스에 사람이 손으로 적어둔 hex 텍스트 라벨이 아님). 2026-09-27 기준으로 캔버스 라벨과 실제 값은 모두 일치한다.
5. **`cn()` 병합 주의**: `cn`(`@shared/utils/cn`)의 충돌 병합은 Tailwind 기본 그룹 기준이라 커스텀 토큰을 모른다. `cn('text-caption', 'text-fg-brand')`처럼 타이포 토큰과 색상 토큰을 함께 넣으면 같은 `text-*` 그룹으로 보고 앞 클래스를 지운다 — 그 조합은 `cn` 대신 문자열 결합을 쓴다 (사례: `features/checkAttendance/ui/AttendanceCheckCard.tsx`).
6. **공용 정책 우선**: 토큰의 색·용도와 기능 제공 범위는 별개다. `../getddo-spec/00-requirements/scope.md`·`02-domain/`의 확정 정책을 우선하며 상태 색 이름만으로 참여 허용·추첨 제외·공통 감사 조회·탈퇴 기능을 제공하지 않는다. 발표 대기는 실제 공개까지 유지하고 단일 발표 요청에서 최종 확인·공개를 함께 처리한다(`03-decisions/022-manual-initial-publication.md`). 배너 이미지 허용 형식·용량은 미확정이며 아래 비율은 FE 권장값이다(`00-requirements/pending-decisions.md`).

### 13) 색 역할 규칙 — 버튼 · 마젠타 · 노랑

토큰 값과 별개로 "어떤 색을 어디에 쓰는가"를 정한 규칙이다. 노랑(응모권, 웜톤)과 마젠타(U+ 브랜드, 쿨톤)는 온도가 달라 섞이면 이질감이 생기므로 **영역과 크기로 떼어 놓는다**.

**버튼**

버튼은 5종이다. 비활성(`surface/disabled` 바탕 + `fg/disabled` 글자, 테두리·hover 없음, `not-allowed` 커서)은 종류가 아니라 모든 버튼에 공통인 상태다. 키보드 포커스는 모든 종류에 `border/focus` 2px 링을 둔다.

| 종류          | 평소                      | hover                                   | pressed                                  | 쓰는 곳                                                                                    |
| ------------- | ------------------------- | --------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| `primary`     | `action/neutral`          | `action/neutral-hover`                  | `action/neutral-pressed`                 | 행동 묶음의 주 행동 — **응모하기**, 확인, 제출, 저장, 출석하기                             |
| `secondary`   | 흰 바탕 + `border/strong` | `surface/canvas` + `fg/disabled` 테두리 | `surface/pressed` + `fg/disabled` 테두리 | 보조 행동 — 취소·돌아가기, 카드마다 반복되는 이동(게임하러 가기, 미션하러 가기), 내역 보기 |
| `ghost`       | 투명, 테두리 없음         | `surface/canvas`                        | `surface/pressed`                        | 아이콘 버튼, 모달 닫기(X), 더보기                                                          |
| `destructive` | `semantic/error`          | `semantic/error-strong`                 | `semantic/error-strong`                  | 허용된 삭제·취소 등 되돌릴 수 없는 행동                                                    |
| `link`        | `fg/primary` 글자         | 밑줄                                    | `fg/secondary` + 밑줄                    | 전체보기, 상세보기 등 글자 이동                                                            |

- primary는 **행동 묶음마다 하나**만 둔다 (페이지 전체에 하나일 필요는 없다).
- **마젠타 버튼은 쓰지 않는다** (`emphasis` 제거). 응모처럼 중요한 행동은 색이 아니라 크기(Large)·자리·확인 모달로 드러낸다.
- **노랑 버튼은 두지 않는다.** secondary hover를 노랑으로 하면 취소 버튼까지 노랗게 변해 어색했다. 보상처럼 노랑으로 강조할 버튼이 필요해지면 그때 `accent` 종류와 hover·pressed 토큰을 함께 정한다.
- secondary hover는 회색 바탕이 비활성과 닮지 않도록 **테두리를 한 단계 진하게**(`fg/disabled`) 바꾸고 글자는 `fg/primary` 그대로 둔다 — 비활성은 테두리가 없고 글자가 연해 구분된다.
- 상세로 **이동**하는 버튼은 "응모하러 가기", 실제로 응모권을 **쓰는** 버튼은 "응모하기"로 이름을 구분한다.
- 모서리 `radius/lg` 8px, 라벨 SemiBold(Small 14 · Medium/Large 16), 높이 Small 36 · Medium 40 · Large 48.

**마젠타 (`brand/*`) — "지금"을 알리는 작은 신호**

- 쓰는 곳: 로고(U+의 +), 현재 메뉴 밑줄, 새 알림 점, 진행 중·실시간 참여 수·오픈 임박 표시.
- 크기: 점, 2px 선, 글자, 작은 칩까지만. **넓은 면이나 버튼 채움에 쓰지 않는다.** 진행 중 표시는 꽉 찬 칩보다 "● 진행중"(마젠타 점 + `fg/primary` 글자)을 권장한다.
- 쓰지 않는 곳: 일반 안내 문구의 목록 점(회색), 선택된 거르기 칩(검정 테두리), 오류(`semantic/error`).

**관리자 hover 규약** — 옅은 hover(`surface/canvas`, `surface/sunken`)가 피드백으로 부족한 관리자 컨트롤에는 `surface/pressed` + `fg/primary`를 쓴다 (관리자 한정으로 `pressed`를 hover에 재사용한다). 표 행은 `surface/sunken`까지만 진하게 하고, 행 안 보조 텍스트는 `fg/secondary`로 두어 hover 상태에서도 대비 4.5:1을 지킨다.

**노랑 (`ticket/*`) — 응모권과 보상**

- 쓰는 곳: 응모권 수(🎟 +N), 등급 응모권, 지갑, 보상 모달, 당첨 연출, 게임·마스코트.
- 넓은 면(`ticket/accent` 바탕)은 보상 화면에만, **한 화면에 하나**만 둔다.
- 고름·진행 같은 상태 표시에 노랑만 쓰지 않는다 — 고름은 진한 테두리(+체크), 진행은 `border/strong` 바탕 위 `action/neutral` 채움이고, 다 채워 보상을 받았을 때만 노랑으로 바꾼다.

**두 색을 맞붙이지 않는다** — 노란 면 위에 마젠타 칩, 마젠타 옆 노랑 버튼처럼 붙이지 말고 사이에 흰색·회색을 둔다.

### 다크 모드

- `<html class="dark">` 기준으로 `tokens.css`의 `.dark` 블록이 `--color-*` 값을 재정의한다.
- 시맨틱 변수(`--background` 등)는 `:root`에서 `var(--color-*)`를 참조하므로 별도 매핑 없이 자동으로 따라간다 — `globals.css`에 shadcn 기본 `.dark` 블록을 두지 않는다.
- 브랜드·응모권·차트 강조색 등 본체 색상은 라이트와 동일하게 유지하고, 배경·전경·보더·soft 배경 계열만 다크 값으로 바꾼다.
- 다크에서도 어두운 크롬(푸터·관리자 사이드바)은 `surface/inverse`를 쓴다 (다크는 페이지보다 한 단계 어두운 값) — `fg/primary`를 배경색으로 쓰는 반전 사용은 다크에서 깨지므로 금지.
- 브랜드 배경 위 텍스트에는 `fg/on-brand`를 쓴다 — `surface/page`를 텍스트색으로 쓰면 다크에서 어두운 글자가 되어 깨진다.

### 화면 설정 (마이페이지)

- 테마: `getddo-ui-settings` persist 스토어(`shared/model/uiSettings.ts`)의 `theme` — 시스템/라이트/다크 중 선택, 기본은 라이트다(OS 다크가 자동 적용되지 않는다). `ThemeSync`(app/providers)가 `html.dark` 클래스를 토글하고, `index.html`의 인라인 스크립트가 React 마운트 전에 저장값을 적용해 라이트 플래시를 막는다. next-themes 시절의 원시 `theme` 키는 1회 마이그레이션된다.
- 큰글씨 모드: `html[data-text-scale='large']`로 루트 `font-size`를 120%로 올린다 — rem 기반 유틸리티에 자동 적용되고, 상태는 같은 `getddo-ui-settings` persist 스토어에 유지된다.

### 미정 사항

> Illustration & Motion 색상(당첨 연출, 응모권 획득 애니메이션, 마스코트 표정 등)은 UI 토큰과 별도로 관리 예정이며 아직 값이 정해지지 않았다. `brand/primary`, `ticket/primary`, `ticket/accent`를 기준색으로 삼고 보조색은 그 주변에서 고르기로 한 상태.

## 4. 이미지 비율

비율은 **그림의 종류가 아니라 자리(쓰임)** 로 정한다. 한 화면 안의 모든 그림을 같은 비율로 맞출 필요는 없고, **같은 역할을 하는 목록끼리만 같으면** 된다. 비율은 둘만 쓴다.

그림 칸은 높이만 고정하고 너비를 칸에 맡기면 화면 폭마다 비율이 달라진다. 비율(`aspect-square`, `aspect-video`)을 고정하고 크기는 너비(목록 줄은 높이) 하나만 정한다.

| 비율     | 자리                                                       | 쓰는 곳                                                                                          |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **1:1**  | 상품을 보여 주는 카드·상세 — 지금 응모할 수 있는 것        | 겟또타임 진행 중·오픈 예정 카드, 래플 상세, 홈 "겟또타임" 대표·오픈 예정, 응모 내역 썸네일       |
| **16:9** | 배너, 그리고 가로로 긴 목록 줄 — 지난 결과처럼 훑어보는 것 | 홈 "응모권 없이 참여할 수 있는 이벤트" 카드, 홈 "발표 대기 · 결과" 줄, 겟또타임 "마감한 래플" 줄 |

**채우는 방식은 그림 종류로 정한다**

- 상품 사진(래플 경품, 대개 흰 배경 누끼): `object-contain` + 여백, `surface/sunken` 바탕에 `mix-blend-multiply`(다크는 `normal`)로 흰 배경을 칸 색에 녹인다 — 16:9 줄에 들어가도 잘리지 않고 흰 띠가 생기지 않는다.
- 이벤트 배너·장면 그림: `object-cover` — 가장자리는 잘려도 된다.

**그 밖의 규칙**

- 그림이 없을 때도 같은 비율의 회색 칸을 둔다(아이콘 없음) — 칸 크기가 그림 유무로 바뀌지 않는다.
- 카드 폭 전체에 상품 그림을 1:1로 깔면 카드가 길어진다. 그런 카드는 1:1 썸네일을 옆에 두는 가로 카드로 만든다 (겟또타임 오픈 예정 카드).
- 같은 역할의 목록은 줄 꼴도 같게 둔다 — 홈 "발표 대기 · 결과"와 겟또타임 "마감한 래플"은 줄 전체 링크, 16:9 썸네일(높이 80), 상태 점, 오른쪽 화살표로 같다.
- 관리자 이미지 등록은 상품 1:1, 배너 16:9를 권장한다.

## 5. 카드 안쪽 여백

여백은 **카드의 역할**로 정한다. 카드 테두리부터 첫 글자까지의 거리를 기준으로 재며, 카드 안 목록 줄이 자체 여백을 가지면 **카드 여백 + 줄 여백의 합**을 맞춘다.

| 여백           | 역할                                                   | 쓰는 곳                                                                                                   |
| -------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| **16** (`p-4`) | 여러 장이 나란히 놓이는 작은 카드 — 훑어보고 고르는 것 | 게임·출석·설문 퀴즈 티켓 카드(공용 TicketCard), 다가오는 이벤트 카드, 게임 상세 기록 칸, 공용 Card 기본값 |
| **20** (`p-5`) | 작은 카드 중 그림과 글이 가로로 놓이는 것              | 겟또타임 오픈 예정·진행 중 축소 카드                                                                      |
| **24** (`p-6`) | 한 영역을 차지하는 내용 카드 — 읽고 조작하는 것        | 미션 출석체크·응모권 내역 카드, 마이페이지 카드, 내 응모권 카드, 겟또타임 진행 중 카드, 관리자 패널       |
| **32** (`p-8`) | 모달·다이얼로그 (좁은 화면은 24)                       | 확인·완료·안내 모달                                                                                       |

- 나란히 놓인 카드끼리는 여백이 같아야 한다 — 미션 페이지의 출석체크와 응모권 내역은 둘 다 24다.
- 목록 줄이 hover 바탕을 위해 자체 여백(`px-4`)을 가지면 카드 쪽 여백을 줄여(`p-2`) 합을 24로 맞춘다.

## 6. 이 문서에 포함되지 않은 것

`04 Button`, `05 Card`는 토큰이 아니라 토큰을 조합한 컴포넌트 스펙이라 제외했다. `04 Button`은 Primary 버튼의 Small/Medium/Large × Default/Hover/Pressed/Disabled 컴포넌트가 이미 만들어져 있고, `05 Card`는 아직 제목만 있고 내용은 비어 있다.
