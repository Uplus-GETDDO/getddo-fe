# GD-255 홈 관리 배너 구현 계획

> 실행자는 승인 후 executing-plans 스킬로 이 세션에서 순서대로 구현한다. 서브에이전트·자동 머지·배포는 수행하지 않는다.

**목표:** B01 관리 배너를 홈에 표시하고 AB01~AB05 변경을 재조회로 반영한다.

**구조:** 기존 banner 엔티티와 manageBanner mutation을 확장하고 기존 bannerSlider 위젯을 이미지 배너로 교체한다. 홈의 겟또타임 안내는 기존 TicketEventSection이 소유한다.

**기술:** React, TypeScript, TanStack Query, Zod, Vitest, 기존 Pager·Button·framer-motion을 재사용한다.

**기준:** ../getddo-spec/05-api/banner.md, ../getddo-spec/02-domain/banner.md, 통합 로드맵 L3.

## 승인 상태와 대조 결과

- 2026-10-20 사용자 승인: 홈 최상단 B01 배치, 기존 추천 배너 제거 및 아래 겟또타임 섹션으로 안내 통합. 별도 화면 담당자 회신을 받은 것으로 기록하지 않는다.
- 2026-10-20 원격 fetch 후 dev와 origin/dev는 063f813, 차이 0건이고 작업 트리는 깨끗했다. GD-255 원격 브랜치는 없었다.
- 기존 대화 ‘배포 점검 및 개선 로드맵 작성’과 현행 문서에서 배치의 명시적 승인은 확인하지 못했다.
- 기존 BannerSlider는 진행 중 겟또타임을 마감순으로 최대 5개 추천한다. B01 스키마·훅은 없다.
- AB01~AB05와 409 후 관리자 재조회, null 이전 배너 표시는 존재한다. mutation은 관리자 키만 무효화한다.
- 관리자 폼에 미확정 형식·5MB 임시 안내가 남아 있다. 수치를 제거하고 담당자 확인 대상으로 표시한다.
- L2의 실서버 추첨 검증·AR01/AR02는 L6 인수 입력이며 L3를 차단하지 않는다. L2 BE 데이터 대기는 유지한다.

## 동작 제안

- 빈 목록은 배너 영역을 숨긴다. 조회 실패는 재시도 안내를 제공한다.
- 이미지는 비율을 유지하고 전체 이미지가 보이도록 표시한다. 실패한 이미지는 실패 안내로 대체한다.
- 연결 이벤트 조회 중·실패에는 잘못된 상세 링크를 만들지 않는다. 실패 안내와 재시도를 제공한다. 정상 조회 후에만 기존 상세 경로로 이동한다.
- B01의 숨김 정책과 상대 순서를 따른다. null 이전 배너는 관리자에 남기며 수정 시 이벤트 선택을 요구한다. 이벤트 취소·삭제로 배너 DELETE를 호출하지 않는다.
- 같은 QueryClient의 변경은 무효화로 반영한다. 다른 세션은 홈 재진입·창 재포커스·명시적 재조회로 새 B01을 받는다. 세션 간 실시간 전파는 추가하지 않는다.
- 실제 이미지 키→공개 URL은 실서버 응답과 이미지 로딩으로 확인한다. 유효한 이미지가 없으면 담당자 입력 대기로 기록하며 업로드 API·제공자·형식·용량을 만들지 않는다.
