# GD-245 R07 모바일 헤더 수정 계획

> 실행자는 `executing-plans` 스킬로 아래 작업을 순서대로 수행한다. 사용자 계획 승인 전 제품 코드를 수정하지 않는다.

**목표:** 모바일 미션 화면에서 사용자명 세로 줄바꿈을 제거하고 로고·메뉴·알림·사용자 전환 접근성을 보존한다.

**구조:** 기존 UserLayout과 VirtualUserSwitcher, Radix Popover를 유지한다. 기존 반응형 클래스와 디자인 토큰으로 공간을 배분하며 메뉴 항목·라우팅·상태관리·API·의존성은 변경하지 않는다.

**기술:** React 19, TypeScript, Tailwind CSS v4, Radix Popover, Vitest.

**기준:** 기존 로드맵 `2026-10-19-development-roadmap.md` R07 및 사용자 GD-245 요청.

## 확인한 상태와 제약

- 시작 브랜치는 dev다. 기존 미추적 로드맵·후속 프롬프트·reports/를 보존한다.
- 헤더는 좌우 24px, 항목 간 30px, 오른쪽 항목 간 20px이며 프로필 이름에 폭 제한과 nowrap이 없다.
- 전체 메뉴는 md부터 노출되며 관리자 버튼·시계도 공간을 사용한다. 일반·관리자 계정을 모두 확인한다.
- 큰글씨는 html[data-text-scale='large']의 120%를 사용한다.
- 디자인 값의 원천은 tokens.css다. DESIGN-SYSTEM.md의 색상·타이포·포커스 토큰을 유지한다.
- KB 자산 카드는 랜딩 페이지용이므로 적용 대상이 아니다. 기존 프로젝트 구현을 사용한다. 오래된 Next.js 체크리스트는 이 Vite 프로젝트의 기술 기준으로 적용하지 않는다.
- 승인 후 원격 GD-245 브랜치 존재 여부를 확인하고 해당 브랜치를 재사용하거나 fix/GD-245를 생성한다.

## 작업 1: 재현과 최소 수정

- [x] 승인 후 executing-plans·webapp-testing 등 실행에 필요한 스킬을 읽고 브랜치를 준비한다.
- [x] 로컬 MSW 실행 조건을 확인한다. 기존 .env를 덮어쓰지 않는다. 브라우저에서 /missions, 390×844, 일반 사용자로 변경 전 캡처와 요소 폭을 기록한다.
- [x] 긴 이름의 접근성 이름과 사용자 전환·Escape·포커스 복귀 테스트를 작성하고 실행해 변경 전 실패를 확인한다.
- [x] 모바일 좌우 패딩과 항목 간격을 줄이고 로고·아이콘의 최소 공간을 확보한다. 프로필은 좁은 화면에서 아바타 중심으로 축약하고 이름을 표시하는 너비에서는 min-width:0·nowrap·ellipsis로 한 줄을 유지한다.
- [x] 기존 메뉴 항목을 유지하며 전체 메뉴 노출 경계를 공간에 맞게 조정한다. 관리자 진입과 시계가 탐색 공간을 침범하지 않게 기존 반응형 표시 조건을 조정한다.
- [x] 사용자 전환 트리거의 접근성 이름에 전체 사용자명을 포함한다. 팝오버는 화면 폭 안에 제한하고 긴 이름은 전체 내용을 읽을 수 있게 처리한다. 기존 사용자 선택 로직과 Radix 포커스 복귀를 유지한다.
- [x] 대상 테스트를 다시 실행하고 diff를 검토한다.

## 승인 범위

위 파일의 기존 UI 수정과 회귀 테스트·증거 문서 작성만 승인 대상으로 삼는다. 새 의존성·설정·환경변수·메뉴 구조 변경은 포함하지 않는다. 커밋·PR·배포는 이번 계획의 필수 단계가 아니다.
