## 실제 브라우저와 목업 테스트의 구분

[브라우저 증거](L4-browser-evidence.json)는 로컬 production preview를 Chromium으로 조작한 결과다. 게임·통계·응모권 요청은 실제 서버로 전달했다. 서비스워커를 차단하고 MSW 비활성 빌드를 사용했다. `/virtual-users` 선택 목록만 등록된 테스트사용자2 fixture로 공급했다. 로컬 포트가 서버 CORS 허용 목록에 없어서 프록시에서 로컬 Origin/Host/Referer를 제거했다. **배포 CORS·L6의 MSW 없는 계정 공급까지 인수한 것은 아니다.**

- 네 게임을 실제 키·버튼 입력으로 자연 종료했고 서버 결과는 색깔 0점·타꼬런 121점·타이밍 0점·주문 0점 모두 VALID였다.
- 타이밍 첫 결과 요청은 서버에 전달한 뒤 응답만 고의 유실했다. 결과 다시 확인 버튼으로 같은 경로·같은 validationData를 재제출해 최초 0점 결과를 받았다.
- 누적 기록과 내 응모권 화면의 T01/T02 요청을 확인했다. 브라우저 계정은 직접 API 보상 검증 계정과 다르다. 새 응모권 지급 대조는 위 API 증거를 사용한다.
- 320px에서 가로 넘침이 없었고 키보드 Tab 포커스를 확인했다. reduced-motion·색상 미디어 조건도 실행했다. 모든 포커스 순서·200% 확대·다크/라이트 대비를 완전 감사한 것은 아니다.
- JavaScript 예외는 0건이었다. 타이밍 유실 주입의 ERR_FAILED는 의도한 장애이며 게임 판정 실패로 세지 않았다. 당시 검사는 localStorage 값의 playToken 문자열만 검색했으므로 실제 토큰 값의 비영속화를 입증하지 못한다. 후속 스크립트는 발급 토큰을 메모리에 수집하고 localStorage·sessionStorage의 키·값을 검사하도록 보완했다. 보완한 실서버 브라우저 검사는 아직 재실행하지 않았다.
- 화면 캡처는 저장소 밖 Codex 시각화 폴더에 보존했다. 재현 스크립트 `scripts/verifyL4Browser.py`는 임시 폴더에 캡처하고 계획 폴더에는 JSON 증거를 쓴다. 로컬 preview 5184와 실제 API 프록시를 사용한다.

자동 테스트에서 명세의 색깔·주문·타이밍 고정 seed 예제, 타이밍 40/50/60점과 포함 경계, 입력 한도, 원본 복제·응답 유실·PROCESSING, ADMIN 제출 생략을 검증했다. KST 자정과 10월 말 경계에서 보상만 일별로 바뀌고 누적 통계·최초 결과가 유지되며, 시계를 되돌려도 같은 날 보상을 다시 주지 않는 것은 **MSW 자동 테스트**다. 72000 tick/endTick71999는 충돌 없는 통제 세계의 자동 테스트다.

## PR #107 리뷰 반영

- 주문의 reveal도 직접 정지 가능한 단계에 포함했다. 탭 숨김·창 blur·정지 버튼 모두 결과 타이머를 멈추고, 이어 하기 후 결과 표시와 다음 주문의 전체 표시 시간을 보장한다. seed·picks·이미 기록한 결과는 바꾸지 않는다. 세 경로를 UI 회귀 테스트로 검증했다.
- 미확정 제출이 있는 상태에서 begin을 누르면 새 G03을 만들지 않고 “이전 플레이의 결과를 먼저 확인”하라는 오류를 표시한다. 원본과 기존 재시도 버튼은 유지한다.
- 규칙값 고정은 채택된 v1 물리·점수 계산과 서버 규칙이 다른 상태로 시작하지 않으려는 의도다. 코드→버전, 공개 보상 안내, 판별용 규칙은 FSD 경계에 따라 각각 존재한다. 새 버전이나 기존 필수 규칙값 변경은 FE 지원을 함께 배포해야 한다. 현재 비교는 기대한 키의 값만 검사하므로 추가 숫자 필드 자체를 거절하지는 않는다. 값 변경 거절·추가 숫자 필드 허용·미지원 버전 거절을 스키마 테스트로 확인했다.
- 색깔 클릭의 인정 범위는 채택 계약의 `0 <= elapsedMs < timeLimit`이다. 정확히 timeLimit이면 null·시간 초과가 의도된 판정이며 변경하지 않았다. 근거는 `getddo-spec/05-api/game-color-word-draft.md`의 시간과 일시정지 절이다.
- pendingSubmissions는 같은 사용자·게임당 미확정 요청 한 건을 페이지 수명 밖에 보존하고 서버 확정 후 삭제한다. 로그아웃 자동 삭제나 임의 TTL은 원본 재시도를 잃게 하므로 추가하지 않았다. 같은 사용자 재진입 복구·다른 사용자에게 미노출·확정 후 제거를 테스트했다. 새로고침/브라우저 종료 시 소실과 영속 저장 미지원 범위는 유지한다.
- 이번 수정은 로컬 회귀 테스트·전체 검사 대상이다. 앞선 실제 API·브라우저 JSON은 L4 최초 연동 당시 증거이며, 리뷰 수정 후 실서버 재검증으로 다시 표기하지 않는다.
- 리뷰 수정 후 검사: format:check·lint·test:ci(95개 파일·696개 테스트)·build·git diff --check를 다시 실행했다. 실서버·실제 브라우저는 이번 수정 후 재실행하지 않았으며 배포 인수 대기는 유지한다.

## CodeRabbit 리뷰 반영

- 주문 정지 화면의 Space·Enter 안내와 키보드 동작을 일치시켰고, 두 키로 reveal 정지를 풀어 다음 주문 전체 표시 시간을 보존하는 테스트를 추가했다.
- 타꼬런은 렌더 프레임당 활성 진행을 최대 0.1초로 제한한다. 긴 지연을 한 프레임에 따라잡아 보이지 않은 장애물에 충돌하지 않게 하며, 서버의 120Hz tick·원본 입력 계약은 유지한다. 5초 지연 다음 프레임이 누적 지연 없이 16ms로 계산되는 테스트를 추가했다.
- 오늘 적립 배너는 통계 실패를 명시적으로 표시하며 실패를 미수령으로 계산하지 않는다. ADMIN·비로그인 세션은 비활성 게임 통계 쿼리를 기다리지 않는다. 응모권 카드는 USER 게임 통계의 최초 로딩까지 기다린 후 정렬한다. L5 미션 계약·처리 로직은 변경하지 않았다.
- 브라우저 검증 스크립트는 POST 성공 응답의 실제 playToken만 메모리에 수집해 localStorage·sessionStorage 키와 값에서 검색한다. 토큰은 증거 JSON에 쓰지 않는다. 검사식은 빈 저장소·별도 키의 원시 값·sessionStorage 값·키 안의 토큰·무관한 값의 5개 로컬 사례를 통과했고 Python 구문 검사를 통과했다. 기존 JSON은 당시 증거 그대로 보존했다.
- 계획의 실서버 미검증 과거 문구를 증거 절 참조로 바꾸고, 위 최초 94개 파일·691개 테스트와 첫 리뷰 후 95개 파일·696개 테스트 기록의 시점을 구분했다.
- 키보드·로딩·오류 동작은 jsdom UI 회귀 테스트로 확인했다. 이번 수정 후 실제 브라우저·실서버·수동 접근성 검증은 수행하지 않았다. L4 전체 완료·배포 인수 대기·L5 이관 조건은 유지한다.
- CodeRabbit 반영 검사: format:check·lint(경고 0개)·test:ci(98개 파일·705개 테스트, 80.92초)·build·git diff --check 모두 exit 0이다. 새 테스트의 lint 위반을 고친 후 해당 테스트·전체 lint·build도 재실행해 통과했다.

## CodeRabbit 재리뷰 후속

- 계획의 자동 테스트 수치를 최초 구현 94개 파일·691개, 리뷰 반영 후 98개 파일·705개로 구분했다.
- verifyL4.mjs의 429 재시도 함수를 공통으로 올려 정상·중복·ADMIN·오류 검증의 모든 결과 PUT에 적용했다. 중복 응답은 양쪽 HTTP 200과 최초 결과의 동일성을 확인하며, 다르면 증거에 실패를 기록하고 프로세스도 실패시킨다.
- 외부 통신을 차단한 로컬 fetch 대역으로 실제 스크립트를 실행했다. 정상 중복·중복 429 후 동일 본문 성공·429 지속 실패·결과 변경 실패의 4개 시나리오를 통과했다. Retry-After 1초의 대기 요청 1100ms도 확인했으며 테스트에서는 실제 대기만 생략했다. 이 결과는 실제 서버 재검증이 아니다.
- 후속 최종 검사: format:check·lint·test:ci(98개 파일·705개 테스트, 77.02초)·build·git diff --check 모두 exit 0이다. node --check와 로컬 스크립트 4개 시나리오도 통과했다.
