# GD-259 L5 이벤트·응모·출석·미션 구현 계획

> 실행자는 `executing-plans` 스킬로 작업별로 구현한다. 사용자 지시에 따라 서브에이전트는 사용하지 않는다.

**목표:** 사용자 상태·수량·재시도 정합성과 출석 정책·미션 관리자 운영을 현행 계약으로 연결한다.
**구조:** 기존 FSD·TanStack Query·Zod·React Hook Form·shadcn을 유지한다. 조회는 기존 엔티티, 행동은 feature, 화면은 관리자 pages에 둔다.
**기술:** React 19, TypeScript, Vite, Vitest, MSW.
**명세:** getddo-spec의 요구사항·scope, event/entry/attendance/mission API와 도메인 규칙, FE ADR-0007·0009, 통합 로드맵 L5.

## 범위와 승인 경계

- 이번 세션은 L5만 수행한다. L6 구현·새 Jira·담당 재배정·자동 머지·실제 배포는 하지 않는다.
- 기존 사용자 경로·계약·인증·의존성·환경 변수·빌드 설정을 유지한다.
- 승인 대상 신규 메뉴: 출석 정책 `/admin/attendance-policies`, 미션 관리 `/admin/missions`.
- 미션 상세·설문 집계·등록은 미션 관리 안의 선택 패널/대화상자로 구성하며 별도 상세·등록 라우트를 추가하지 않는다. AdminGuard와 lazy 로딩을 유지한다.
- 신규 feature: `manageAttendancePolicy`, `manageMission`. 출석 예약 등록과 미션 등록만 제공하며 수정·삭제·DRAFT·승인/반려는 만들지 않는다.
- 담당 경계는 기존 이벤트 장준환·출석/미션 박소연·공통 지원 송동현을 유지한다. 이 계획의 실행 승인을 담당 재배정으로 기록하지 않는다.

## 승인 상태

## 실행 결과와 외부 인수

구현·로컬 검증과 실제 API 조회/사용자 보상 검증 결과는 [검증 보고서](../../../reports/20261020-GD-259-L5.md)와 [L5 인계](L5-handoff.md)에 연결한다. 체크 완료는 각 단계에서 명시한 검증 수준을 뜻하며 관리자 격리 쓰기·실제 다문항/자정/월 경계/취소 반환·배포 인수는 완료로 확대하지 않는다. PR·머지·배포는 없고 L6 구현은 다음 새 세션으로 남긴다.

최종 검사: format:check·lint·test:ci(112개 파일·750개 테스트, 60.02초)·build·git diff --check exit 0. 최종 브라우저 19개 항목·37개 요청·JS 예외 0건이며 실제 응답과 주입을 종류별로 구분했다.
