# GD-246 응모권 이력 조회 검증

- 날짜: 2026-10-19 KST
- 환경: 로컬 Windows, `refactor/GD-246`, QueryClient + MSW + jsdom
- 범위: R08의 T02만 구현. 이벤트·미션 목록·응모 목록 개편은 제외했다.
- 변경: 자동 전체 커서 수집을 원시 이력 5건의 첫 페이지와 명시적 더보기로 전환했다. 필터별 캐시, 다음 페이지 실패 복구, 중복 커서 중단, 만료·반환 병합을 추가했다.
- 합계: 기존 T02의 조건별 `totalElements`를 사용한다. 월·일 합계는 로드된 목록을 합산하지 않는다. 새 의존성·API 계약·설정 변경은 없다.

## 전후 요청 수

일반 이력 단독 조회이며 합계·T01·다른 도메인 요청은 제외했다. 기존 코드에 먼저 실행한 테스트에서 1000건은 실제 10요청, size=100으로 확인했다. 변경 후 값은 실제 MSW HTTP 요청을 기록한 테스트 결과다. 기존 0/5/6건도 최초 1요청이었으며 size=100 검증에서 실패했다.

| 전체 원시 이력 | 이전 최초 요청 | 변경 후 최초 요청 / 로드 행 | 더보기 1회 후 누적 요청 / 로드 행 |
| -------------- | -------------- | --------------------------- | --------------------------------- |
| 0              | 1              | 1 / 0                       | 1 / 0, 더보기 없음                |
| 5              | 1              | 1 / 5                       | 1 / 5, 더보기 없음                |
| 6              | 1              | 1 / 5                       | 2 / 6, 종료                       |
| 1000           | 10             | 1 / 5                       | 2 / 10, 후속 커서 유지            |

화면별 T02 요청도 실제 QueryClient와 MSW로 검증했다. 아래 요청 수는 신규 캐시의 최초 진입 기준이다.

| 화면        | 최초 T02 요청                     | 합계 의미·결과                                                        |
| ----------- | --------------------------------- | --------------------------------------------------------------------- |
| 응모권 지갑 | 4, 모두 size=1                    | 월 GRANT 1000 + REFUND 20 = 적립 1020, USE 300 + EXPIRE 40 = 사용 340 |
| 내 응모권   | 3 = 이력 1 + 월 합계 2            | 월 받은 1000, 쓴 300. 더보기 후 누적 4요청                            |
| 마이페이지  | 2 = 최근 7일 이력 1 + 오늘 합계 1 | 최근 원시 5건, 오늘 GRANT 전체 1000                                   |

미션 화면의 이력과 지갑이 함께 마운트되면 기본 이력 1 + 월 합계 4 = 최대 5요청이다. 이는 각 영역의 검증된 요청 수를 합친 계산이며 미션 화면 전체의 별도 실측값은 아니다. 동일 조건 캐시는 공유한다. 만료·반환 필터의 최초 요청은 2회이고 더보기당 최대 2회다. 기존의 전체 이력 공유보다 소량 데이터의 요청 수는 늘 수 있지만 이력 전송량은 고정 상한으로 제한된다.

새로 추가한 검증은 API 19개, 기간 유틸 2개, 미션 소비자 7개, 실제 HTTP 그룹 경계 1개, 화면 통합 4개다.

- 중복 id, A→A 및 A→B→A 커서, 빈 비정상 페이지, 요청 연타, 다음 페이지 오류와 같은 커서 재시도, 필터 변경 중 지연 응답·캐시 분리·tickets 접두사 무효화를 검증했다.
- 두 유형의 버퍼 병합, 한 유형 조기 종료, 부분 실패, 짧은 페이지, 가변 소수 초·나노초 정밀도·동시각 id 정렬을 검증했다.
- KST 월·일 경계, 월 합계 실패 시 0 오표시 방지와 독립 복구, 다섯 번째/여섯 번째 원시 이력이 같은 그룹일 때 수량 갱신을 검증했다.
- 독립 리뷰에서 발견한 가변 소수 초 정렬 문제는 실패 테스트로 재현한 뒤 수정했다. 재시도 버튼 잠금 누락도 수정했다.
- 계정 전환 시 기존 `sessionSync.ts`의 `queryClient.resetQueries()`가 새 키와 초기 커서에도 적용되는 구조를 정적으로 확인했다. 별도 실제 계정 전환 통합 테스트는 추가하지 않았다.
- 샌드박스 실행 중 Vite 임시 모듈 ENOENT가 발생해 전체 테스트는 승인된 샌드박스 밖 실행으로 재검증했다. 마지막 전체 테스트도 511개 모두 통과했다.

## 제한과 후속

- 요청 수는 모의 서버에서 측정했다. 실서버 SQL 비용·지연 시간은 측정하지 않았다. `totalElements` 조회 비용도 서버 구현에 달려 있다.
- 서로 다른 합계 요청 간 원자적 스냅샷은 기존 계약이 보장하지 않는다. 단일 집계 API가 필요하면 별도 계약 승인 대상이다.
- 목록의 기간 상한은 진입·필터 변경 시 고정하고 가상 시계 이동·KST 날짜 변경 시 갱신한다. 일반 렌더마다 새로운 캐시를 만들지 않는다.
- 그룹 수량은 불러온 원시 이력 기준임을 화면에 안내한다. 월 전체 합계와 분리했다.
- 접근성 로딩·오류 상태와 버튼 잠금은 정적 검사·Testing Library로 검증했다. 실제 브라우저 키보드·320px·200% 확대 검증은 수행하지 않았다.
- 커밋·push·PR·머지·배포는 수행하지 않았다. 기존 미추적 산출물 3개는 보존했다.
- 롤백이 필요하면 GD-246 변경 파일만 되돌리고 기존 미추적 문서는 유지한다.
