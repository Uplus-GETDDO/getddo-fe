## 실제 브라우저와 목업 테스트의 구분

[브라우저 증거](L4-browser-evidence.json)는 로컬 production preview를 Chromium으로 조작한 결과다. 게임·통계·응모권 요청은 실제 서버로 전달했다. 서비스워커를 차단하고 MSW 비활성 빌드를 사용했다. `/virtual-users` 선택 목록만 등록된 테스트사용자2 fixture로 공급했다. 로컬 포트가 서버 CORS 허용 목록에 없어서 프록시에서 로컬 Origin/Host/Referer를 제거했다. **배포 CORS·L6의 MSW 없는 계정 공급까지 인수한 것은 아니다.**

- 네 게임을 실제 키·버튼 입력으로 자연 종료했고 서버 결과는 색깔 0점·타꼬런 121점·타이밍 0점·주문 0점 모두 VALID였다.
- 타이밍 첫 결과 요청은 서버에 전달한 뒤 응답만 고의 유실했다. 결과 다시 확인 버튼으로 같은 경로·같은 validationData를 재제출해 최초 0점 결과를 받았다.
- 누적 기록과 내 응모권 화면의 T01/T02 요청을 확인했다. 브라우저 계정은 직접 API 보상 검증 계정과 다르다. 새 응모권 지급 대조는 위 API 증거를 사용한다.
- 320px에서 가로 넘침이 없었고 키보드 Tab 포커스를 확인했다. reduced-motion·색상 미디어 조건도 실행했다. 모든 포커스 순서·200% 확대·다크/라이트 대비를 완전 감사한 것은 아니다.
- JavaScript 예외는 0건이었다. 타이밍 유실 주입의 ERR_FAILED는 의도한 장애이며 게임 판정 실패로 세지 않았다. playToken을 localStorage에 쓰지 않음을 확인했다.
- 화면 캡처는 저장소 밖 Codex 시각화 폴더에 보존했다. 재현 스크립트 `scripts/verifyL4Browser.py`는 임시 폴더에 캡처하고 계획 폴더에는 JSON 증거를 쓴다. 로컬 preview 5184와 실제 API 프록시를 사용한다.

자동 테스트에서 명세의 색깔·주문·타이밍 고정 seed 예제, 타이밍 40/50/60점과 포함 경계, 입력 한도, 원본 복제·응답 유실·PROCESSING, ADMIN 제출 생략을 검증했다. KST 자정과 10월 말 경계에서 보상만 일별로 바뀌고 누적 통계·최초 결과가 유지되며, 시계를 되돌려도 같은 날 보상을 다시 주지 않는 것은 **MSW 자동 테스트**다. 72000 tick/endTick71999는 충돌 없는 통제 세계의 자동 테스트다.
