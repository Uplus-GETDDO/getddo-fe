# GD-259 L5 검증 기록

기준일: 2026-10-20 KST. 범위는 이벤트·응모·출석·미션 사용자 정합성과 관리자 출석·미션 운영이다. L6 구현·서브에이전트·Jira 생성·담당 재배정·원격 발행·머지·배포는 수행하지 않았다.

## 구현과 정책

- 사용자 이벤트는 취소 `canceled`, 대상 없는 종료 `ended`, 공개 `drawn`, 공개 전 `closed`를 구분한다. `DRAW_CONFIRMED/REDRAWING`의 내부 진행·사유는 사용자에게 노출하지 않는다. E08 공개 상태가 결과 노출을 결정하며, 취소 상세는 오래된 공개 결과가 있어도 취소 안내를 우선한다.
- GD-247의 E03/E08/E09 종결·429·표시 행 폴링을 유지한다. E09의 CANCELED만으로 폴링을 종료하거나 행마다 E08을 추가하지 않았다. E01/E02·출석·미션·신규 관리자 조회에는 기존 읽기 오류 가드를 재사용했다.
- 이벤트 취소 성공은 기존 관리자 키와 함께 사용자 이벤트·응모·응모권·B01 배너 키를 무효화한다. 다른 세션은 기존 재조회 정책으로 반영하며 전역 실시간 동기화를 약속하지 않는다.
- E01/E06은 전체 수집을 유지하며 총 건수에 못 미친 빈 중간 페이지를 성공으로 확정하지 않는다. 실패하면 이전 전체 목록·합계와 성공 시각을 보존한다. 조회 중 데이터가 바뀌는 번호형 페이지의 원자적 스냅샷을 보장하는 변경은 아니다.
- 퀴즈는 부분 답변을 제출하며 정답 누적은 서버가 판정한다. 문항별 정답 진행 API를 만들지 않았다. 설문은 모든 필수 문항을 요구한다.
- 미션 불확정 실패·5xx·429에는 키·원본 답변을 유지하고 원본 재확인 버튼을 제공한다. 성공한 오답 뒤에는 새 키를 쓴다. 원본은 해당 폼 수명의 메모리이며 새로고침·폼 종료 후 복구는 지원하지 않는다.
- 출석은 동시 클릭·429 대기를 가드한다. 달력·보상 안내는 서버 출석 기준일·확정 영수증을 따르며 재요청 보상을 새 지급처럼 안내하지 않는다.
- 관리자 `/admin/attendance-policies`는 AP01~AP04, `/admin/missions`는 AM01~AM04를 소비한다. 등록·예약은 `manageAttendancePolicy`/`manageMission` feature가 담당한다. AdminGuard·lazy·FSD·기존 Query 키 무효화를 유지했다.
- 출석 예약은 다음 KST 기준일/기준월을 서버가 정한다. 중복 예약 ATTENDANCE-004/005는 재조회·충돌 안내로 처리한다. 예약 수정 API는 없다.
- 미션 등록은 즉시 ACTIVE·보상 1장이다. 퀴즈 정답과 설문 필수 여부를 구분하고 관리자 정답 DTO를 사용자 DTO에 합치지 않는다. AM04는 양끝 포함 최대 31일·완료 설문·선택형 문항만 집계한다.
- 자동 당첨 취소·이용 제한·추첨 제외 안내와 결과 재현율 100% 문구를 정리했다. 개발 목업의 미션 보상·누적 정답 및 이벤트 재취소 계약도 정렬했다. 테스트용 목업과 L6의 런타임 목업 종료는 별개다.

## 실제 브라우저와 응답 주입의 구분

[브라우저 증거](../docs/superpowers/plans/L5-browser-evidence.json)는 MSW 비활성 로컬 production preview와 Chromium을 사용했다. 업무 조회는 실제 서버로 전달하고 `/virtual-users` 목록만 시연 fixture로 공급했다. 로컬 CORS를 피하려고 요청의 Origin/Host/Referer를 제거하는 프록시를 사용했으므로 배포 CORS·L6 계정 공급 인수를 의미하지 않는다.

- 실제 요청: AP01/AP03·AM01/AM02/AM04, 사용자 상세·결과 조회. 각 요청에 상태와 종류를 기록했다.
- 주입: AP02 409·AP04 201, AM03 201 등록 성공, GET 503·429, 빈 목록, 실제 이벤트 상세의 CANCELED 상태. 관리자 POST는 실서버로 전달하지 않았다. 등록 폼의 KST→UTC·보상 1장도 검증했다.
- UI: 320/390/640px 가로 넘침 없음, dark/light·reduced-motion 실행, 키보드 포커스 확인. 640px은 반응형 검사이며 실제 브라우저 200% 확대의 완전 인수로 계산하지 않는다.
- 복구: 실제 성공 목록 뒤 503에서 기존 행 보존, Retry-After 2초의 즉시 재클릭 우회 차단·대기 뒤 실제 API 재조회, 실제 브라우저 offline→online 전환에서 성공 행 보존을 확인했다.
- 취소: 기본/겟또타임 상세 경로에서 취소 안내·응모 차단. 결과 조회가 기존 WAITING인 경우에도 이벤트 취소를 발표 대기로 표시하지 않았다.
- JavaScript 예외 0건, Service Worker 등록 0건. 이미지 캡처는 저장소 밖 Codex 시각화 폴더의 `L5/`에 보존했다.

## 자동 테스트와 검사

상태 변환, 전체 페이지 수집·실패 보존, 브론즈/멤버십/누적 5장/월말 예외, 원등급 반환·당첨 취소 무반환, 출석 일일·월 경계·31일·단계 재달성, 미션 부분 제출·누적 정답·1장·멱등 재시도, AP 입력/409/403·AM 스키마/기간/빈 화면을 검증한다. 목업 테스트는 서버 트랜잭션·동시성 증거가 아니다.

최종 format:check·lint·test:ci(112개 파일·750개, 60.02초)·build·git diff --check는 모두 exit 0이다. 기본 test:ci 명령으로 전체 통과했고, 브라우저 최종 실행은 19개 항목·37개 요청·JS 예외 0건이다. 명령과 결과는 [L5 인계](../docs/superpowers/plans/L5-handoff.md)의 검사 표에 기록한다. 최초 전체 검사에서는 재시도 1초와 배너 테스트 1초 대기 충돌, Query 추적 속성 누락, 기존 추첨 테스트의 부하 시 대기 실패가 발생했다. 정책을 약화하지 않고 배너 검증 대기를 실제 재시도 이상으로 맞추고 새 테스트의 상태 구독을 수정했다. 제한 worker 실행은 설정 파일 변경 없이 CLI로 수행했다.

## 미검증·외부 입력

- AP02/AP04 정책 예약 정상 쓰기·서버의 다음 KST 기준일/기준월 적용·실제 중복 예약 409, AM03 관리자 실서버 등록은 전용 격리 환경이 필요하다. 현재는 계약·모델·브라우저 주입 검증이다.
- 실제 다문항 퀴즈 누적 정답, 실제 필수 누락 거절·응답 유실·429 재전송, 자정·월 경계·연속 보상, 이벤트 취소 반환·당첨 취소 무반환은 격리 시나리오 표본이 필요하다. 자동 테스트를 실제 서버 인수로 바꾸지 않았다.
- 실기기 터치·200% 확대·모든 대비/포커스 순서·배포 Worker/CORS·배포 후 전체 동선·성능 p95는 L6 인수 대상이다.
- 독립 리뷰어·원격 CI·PR·머지·배포는 아직 없다. 사용자가 실제 배포를 금지했고 PR은 자동 Preview를 유발할 수 있어 로컬 검증·커밋까지만 진행한다.
