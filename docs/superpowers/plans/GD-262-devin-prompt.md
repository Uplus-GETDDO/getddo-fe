# Devin 재개 프롬프트

GD-262 「[FE] 주요 화면 성능 측정 및 조회 최적화」를 이어서 진행해줘.

저장소는 `https://github.com/Uplus-GETDDO/getddo-fe.git`, 작업 브랜치는 `perf/GD-262`야. 현재 폴더가 저장소라고 가정하지 말고 실제 저장소와 브랜치·미커밋 변경부터 확인해줘. 작업 기준 원본은 `88f4970a0af3055eb642f56a0052804260d1c0ff`야.

먼저 다음 문서를 읽어줘.

1. `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, 공용 명세 저장소의 관련 계약.
2. `docs/superpowers/plans/GD-262-handoff.md` — 완료분·부분 표본·재현 명령·남은 작업이 있는 인계 원본.
3. `docs/superpowers/plans/2026-10-21-GD-262-performance.md` — 이미 사용자가 승인한 계획.
4. `reports/20261021-GD-262-performance.md`, `reports/GD-262/handoff-state.json`, L1~L6 로드맵과 기존 검증 기록.

이미 사용자 화면 지연 로딩을 구현했고 이번 변경의 전체 테스트 115파일·759개와 빌드는 통과했어. 초기 JS gzip은 399,821→345,530B(-13.58%)지만 전체 JS는 +0.65%야. 화면 전환 비용까지 재측정한 뒤 최종 채택 여부를 판단해줘. 과거 758개 통과 기록을 이번 변경의 근거로 쓰지 마.

**작업은 미완료야.** 실서버 데이터가 이벤트 26→28개로 변해 동일 조건 비교를 위해 고정 응답 재생으로 전환했어. 통제 기준선은 132회 중 111회 시도(유효 105·링크 없음 6)에서 중단했고, 변경 후 통제 측정과 홈 n=30은 아직 실행하지 않았어. 부분 자료·diagnostic 자료를 완전한 전후 비교로 쓰지 마.

사용자는 이미 “구현 진행해줘”와 **“축소 측정 후 주요 화면 30개 검증”**을 승인했어. 일반 화면 11개×4조건(초기/전환/5초 재방문/35초 재방문), 조건당 n=3과 홈 n=30으로 진행해줘. 새 호스트에서 Windows 부분 표본과 합산하지 말고 같은 호스트·빌드 옵션·브라우저·고정 데이터·지연·표본 수로 양쪽을 다시 측정해줘. fixture 원문은 Git 밖에 보관하고 결과에는 해시·건수만 남겨줘.

현재 측정 스크립트의 Playwright 로딩 경로는 Codex Windows 번들 기준이므로 Devin의 기존 도구에 맞게 조정해야 해. 새 의존성·API 계약·DB·auth·아키텍처·빌드/환경 정의 변경은 별도 승인 대상이야. 기존 .env를 덮어쓰지 말고 운영 API 쓰기는 하지 마. 기존 API GET·신선도·폴링·전체 합계·사용자 전환 격리를 보존해줘.

인계 문서 순서에 따라 남은 통제 비교·홈 30개·체류/모달/페이지 이동/데스크톱/101개 이벤트 보조 실험과 브라우저 회귀 검사를 실행해줘. 실제 API 왕복과 화면 표시 시간을 분리하고, 통제 50ms 응답을 실서버 p95로 해석하지 마. n=3 p95는 최댓값이며 안정적인 모집단 p95가 아니야. 일반 클릭→결과 표시 목표는 문서에 없으므로 **목표 미확정**을 유지해줘. 실제 공개→표시 2초·응모 쓰기·BE 내부/부하·알림 생성 목표를 이번 GET 실험으로 통과 처리하지 마.

필요한 수정 후 format·lint·전체 테스트·build와 성능 재측정을 실행하고, 계획·보고서·로드맵에 실제 결과와 미검증을 구분해 기록해줘. BE 변경 후보는 별도 후속 항목으로 남겨줘. 다른 작업 파일을 덮어쓰지 말고, 머지·배포는 하지 마.
